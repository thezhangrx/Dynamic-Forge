# v0.5.2-LTVGuarded — LTV override guard

## 1. Problem

v0.5.1-LongTermViability let LTV *authoritatively* re-rank candidates: the
bucketed arbitration compared `viability_cost` directly after the risk band, so a
small long-term mobility difference could replace the v0.4.1 short-term choice.
The 1000-episode run regressed against the strict v0.4.1 reference:

| | v0.4.1 reference | v0.5.1 LTV ON |
|---|---|---|
| collision | 61.7% | 70.4% |
| survival | 958.2 | 924.6 |
| decision | 1297.7 µs | 1878.2 µs |
| LTV override | — | 18.96% |
| side_hit | — | 451 |
| corner_trap | — | 71 |

Diagnosis: the regression is caused by LTV overturning v0.4.1 decisions, not by
the v0.4.1 core.

## 2. Strategy

LTV is demoted from **primary re-ranker** to **guarded advisory tie-break**:

```
v0.4.1 short-term best  (FAR + ASE + hard feasibility + v0.4.1 hysteresis)
        │
        ├── kept by default
        │
        └── LTV proposal (unchanged v0.5.1 chain: shortlist → anchors →
            mobility → bucketed arbitration → corridor/action hysteresis)
                    │
                    ▼
            OVERRIDE GUARD  (all conditions must hold)
              A. candidate feasible                    (upstream)
              B. critical band not worse than reference
              C. risk band EQUAL to reference          ← never cross a bucket
              D. viability gain ≥ 0.10
              E. not long-term degraded
              F. not EmergencyFallback                 (upstream)
                    │
        pass ───────┴──────> apply proposal
        fail ──────────────> keep short-term best
```

Why this lowers meaningless overrides:

* **C** removes the dominant failure mode — LTV choosing a candidate in a
  *different* risk bucket (−6,817 candidate blocks in the 5-episode smoke).
* **D** removes the "tiny viability difference" overrides (the v0.5.1 pathology):
  a small score wobble can no longer change the action.
* **E** stops a candidate that scores well on one anchor from winning while its
  escape corridor is actually worse.
* **B/F** keep hard safety and the emergency fallback absolutely untouched.
* If the v0.4.1 choice is not on the LTV shortlist there is no reference to beat,
  so nothing overrides (`no_ltv_reference`).

FAR/ASE remain the primary decision; LTV only avoids obvious long-term dead ends
among candidates that are *short-term equivalent* (same risk band).

## 3. What did NOT change

FAR, ASE (including the documented ASE/LTV dynamic-buffer deferral), SafetyGate,
FES, dwell, adaptive horizon, adaptive smooth, the 17 base candidates, ≤8 local
refinement, threat-aware speed, EmergencyFallback, Top-K=4 (3 leaders + 1 LTV-blind
diversity), future agent × future obstacle mobility, 3 anchors, corridor
hysteresis, action hysteresis, `max_dynamic_buffer`, `risk_band_width=0.05`, and
the whole bucketed arbitration chain. `far.py` is untouched. No new weighted
objective was introduced.

`corridor_hysteresis` still runs, but if the guard vetoes the proposal the
corridor memory is rolled back to its pre-frame value, so the hysteresis state
never describes a corridor that was not taken.

## 4. Controls

| env | default | effect |
|---|---|---|
| `DF_ENABLE_LTV=0` | on | strict v0.4.1 reference path; LTV never evaluated |
| `DF_LTV_SHADOW=1` | off | run all of LTV + diagnostics, never change the action |
| `DF_LTV_GUARD=0` | on | restore raw v0.5.1 arbitration (A/B only) |
| `DF_LTV_DEBUG=1` | off | per-frame `[LTV]` trace (print-only) |

`ViabilityConfig` guard parameters:

* `guard_enabled = True`
* `viability_improvement_threshold = 0.10`
* `long_term_degraded_margin = 0.0`

## 5. Observability

`PlanDiagnostics` adds: `ltv_shadow`, `ltv_guard_enabled`, `ltv_proposed_index`,
`risk_band_delta`, `long_term_degraded`, `override_guard_reason`,
`override_candidate_count`, `override_blocked_by_{risk_band,viability_margin,
long_term_degraded,critical_band,no_reference}`, and an `override_reason` alias.

The benchmark reports `proposed_override` (what LTV wanted), `override` (what was
allowed), `guard_veto`, and the per-condition block histogram.

## 6. Smoke evidence (5 episodes, seed 42)

| metric | raw v0.5.1 (`DF_LTV_GUARD=0`) | v0.5.2 guarded |
|---|---|---|
| override rate | 19.96% | **0.55%** |
| override steps | 986 / 4939 | 26 / 4745 |
| proposed override | 19.96% | 35.51% |
| guard veto | — | 34.96% |

The guard removes ~97% of LTV overrides while leaving LTV active (26 applied
overrides). `docs/benchmark_results.md` is only regenerated by
`benchmark_decision.py`; this round ran no 1000-episode benchmark.

## 7. Episode logging & paired analysis (diagnostics infrastructure)

No control code, no guard parameter and no decision order is involved. Each
episode now also yields a JSON-serializable record:

```
seed, collision, collision_step, failure,
override_seen, override_steps, last_override_step,
last_override_step_before_collision,
steps_since_last_override_before_collision,
seconds_since_last_override_before_collision,
survived, changes, override_count, decisions
```

`override_steps` contains **only overrides that actually passed the guard**; a raw
LTV proposal or a guard veto is never recorded there. `seconds_...` uses
`CONTROL_HZ = 120.0` (steps / 120), matching the existing `dt = 1/120`.

Where it is written:

| command | output |
|---|---|
| `tools/ltv_regression_diagnostics.py --mode on --episodes-jsonl P` | `P.guarded.episodes.jsonl` |
| `tools/ltv_regression_diagnostics.py --mode off --episodes-jsonl P` | `P.off.episodes.jsonl` |
| `tools/ltv_regression_diagnostics.py --mode both --episodes-jsonl P` | both, then the paired report |
| `DF_EPISODES_JSONL=P .venv/bin/python benchmark_decision.py` | `P.reactive.episodes.jsonl`, `P.predictive.episodes.jsonl` |

In `both` mode the tool inner-joins the two logs by `seed` and **raises** on a
duplicate seed, a differing episode count, or any unmatched seed — nothing is
silently dropped. It then reports the 4-cell table (`both_collision`,
`both_survive`, `off_survive_on_collision`, `off_collision_on_survive`), checks
the total equals the episode count, computes `on_gain`/`on_loss`/
`net_episode_delta` and verifies `net == off_collision_total − guarded_collision_total`,
the per-failure bidirectional transitions (final episode failure only), the
override outcome split (`override_episode_survived` + `override_episode_collided`
== `override_episodes`), and the override-to-collision timing histogram
(`<0.10 / 0.10-0.25 / 0.25-0.50 / 0.50-1.00 / 1.00-2.00 / >2.00 / none`), overall
and per failure type.
