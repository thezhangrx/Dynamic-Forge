## 接口契约（已核实）

基址 **0x43C00000**（4 KB 窗口，mmap `/dev/mem`）：

| 偏移 | 名称 | 说明 |
|---|---|---|
| 0x000 | CONFIG | 21 个参数寄存器（阈值等；必须与 `vision_ref.c` 的 `VR_DEFAULT_*` 一致） |
| 0x080/0x084 | DBG | 写 `{sub[3:0],idx[17:0],sel[3:0]}`，读数据（统计/直方图/列投影/行带） |
| 0x0C0 | CTRL | 写 bit0=1 启动一帧（自清）；读 bit0=busy bit1=done bit[15:8]=fcount bit16=ovf |
| 0x0C4/0x0C8/0x0CC | SEQ/STAMP | 帧序号 + 纳秒时间戳（进帧头） |
| 0x0D0 | FLEN | 只读：上一帧实际字节数 |
| 0x0D4 | PIXPUSH | 写：像素 FIFO，**整字 4 字节** |
| 0x0D8 | PIXSTAT | 读：[15:0] 缓冲字节 [16] 溢出 [17] 正在放 |
| 0x0DC | PIXCTL | 写：bit0 像素源（0=外部/TPG，1=FIFO）bit1 flush |
| 0x100 | FRAME | 几何帧字节窗口（2048 B） |

**喂帧顺序（关键）**：`PIXCTL=0b11`（flush）→ `PIXCTL=0b01` → 写 SEQ/STAMP →
**写 CTRL bit0=1 启动** → 推像素（整字）→ 等 busy 落 → 读 FLEN/窗口。
（先推像素再 start 会死等：IDLE 时推的像素被丢掉。）

**几何帧布局**（`core/board/geometry_frame.hpp`）：

```
头部 32 B : magic 'BHV1'(0x31564842) | ver u16=1 | flags u8 | seq u32 |
            n_obs u8 | n_gaps u8 | width u16 | height u16 | stamp_ns u64
body      : player 16 B + target 24 B + obstacles 36×n_obs + gaps 36×n_gaps
trailer   : CRC32(zlib) 4 B
总长      = 76 + 36*(n_obs + n_gaps)，必须 == FLEN
```

## 🎯 round 6：找到 PL 判不出墙的**直接原因**（RTL 侧，实测）

在板上直接读 `PIXSTAT.buffered`（`0x0D8`），逐次推字：

```
flush 后 buffered = 0
推第 1 个字（32 位写 0x0D4）→ buffered = 12   （+12 = **3 个字**）
推第 2 个 → 24   （再 +12）
...
对照：8 位写 0x0D4 → buffered +4（1 个字）
```

→ **一次 32 位 AXI 写会让像素 FIFO 进 3 份同样的字**。整帧于是被 3 倍重复，
流水线看到的画面必然错位 ⇒ `n_obs=0`；而帧长/CRC 仍然自洽（所以一直没被发现）。
cosim 里没暴露，是因为仿真模型的 AXI 从机每笔写只提交一次。

同一批帧、同一份字节、同一份参数，唯一差的就是这条写通道。

### 修法

RTL 侧：`vision_axi.v` 的 `W_PIXPUSH` 分支要在"一笔写只脉冲一次"上做一次性保护
（或查清 GP 口为什么对一次 32 位 store 提交 3 次）。改完必须重出位流。

⚠ **round 6 的数字读法有误，round 7 已订正**（见下一节）：`buffered` 是"边录边排空"
的活计数，不能当计数器；"3 份"的真实内容是"1 份数据 + 2 份空选通写"。

## 🎯 round 7：用整张灰度图取证 → 本地复现 → 按 AXI 语义修掉（2026-10-24）

### 1) 板上 L0（当前位流，md5 与 out/ 一致，RTL 与仓库只差注释）

```
C 参考：000000/000001/000002.ppm 各 n_obs=8 n_gaps=4 player=1 bands=4 span=[80,559]
板上 PL：同三帧全部 n_obs=0 n_gaps=0（帧长 76 / CRC 却自洽）
```

`buffered` 复测**自相矛盾**（同一笔 store：ctypes 读 +4、`pack_into` 读 +12、
8 位写读 +8、16 位写读 +12）→ 它是"FIFO 字数*4 + 蓄水池字节"的**瞬态**读数，
round 6 那条 `+12 = 3 个字` 不能用。

### 2) 定位图案 + 整张灰度图相关（决定性）

- 白点在 `(0,0)/(320,180)/(639,359)` 三处：**只有 (0,0) 那一个到了**，且被拆成
  `(0,0,255)`+`(255,255,0)` 两个像素 → 像素栅格错位。
- 白点 `idx 6700` 出现在 `idx 20102`（≈3×）。
- 随机图案整帧读回 230400 个灰度：与参考做「像素平移 / 字节平移 / 字节置换 /
  1 字重复 3 次」全搜索，**最佳只有 25%**；自相关给出**严格周期 4**，
  图案是 `[0,0,x,y]`（每 4 个像素里 2 个是 0）。

→ 结论：像素流里**每个 32 位字变成了 12 字节（4 数据 + 8 个零）**。

### 3) 本地复现（R1d：先在仿真里证明，再动板子）

给 `cosim/tb_axi.cpp` 加 `--mimic-gp`：每个像素字发 **1 笔 strb=0xF + 2 笔 strb=0x0**。

```
修前：--fifo --mimic-gp         → 比对项 1276，不符 149
      TB_DUMP_GRAY=20 打出     → RTL gray = 13,3,0,0,17,4,0,0,…（周期 4，两零两真）
                                  板上实测 = 0,0,17,124,0,0,9,58,…（同一形状，差相位）
```

→ **真硅上一次 32 位 store 确实变成 3 笔 AXI 写**（GP 口/互联的数据通道拆分），
其中 2 笔 `WSTRB=0`。原 `W_PIXPUSH` 不看待选通，把 3 笔都压进 FIFO。

### 4) 修法（按 AXI 语义，不是"打补丁"）

`vision_axi.v` 的 `W_PIXPUSH`：

- `WSTRB == 0` → **不携带任何字节，不压**（并累加诊断计数 `0x0EC`）；
- 部分字节写 → 按字节合并，等 4 个字节选通都到齐再压 1 个字；
- 整字写（`strb=0xF`）→ 仍是一拍压一次（快路径、cosim 行为不变）。
- `push_data` 改用合并后的 `pix_acc`。

### 5) 本地验证（全部 0 不符）

```
./obj_dir/Vvision_axi … --fifo                     → 比对项 2229，不符 0
./obj_dir/Vvision_axi … --fifo --mimic-gp          → 比对项 2229，不符 0（修前 149）
./obj_dir/Vvision_axi … --fifo --mimic-gp --word-gap 142 → 1707，不符 0
```
（`--word-gap 142` 是板上实测的喂数节奏：490 ms/帧 ≈ 每 142 拍一个字；
慢喂本身在修前也是通过的，所以它不是原因。）

### 6) 真凶不是 AXI 拆包，而是**喂数器的写法**（板上逐个排除）

加了 FIFO 内省寄存器（`0x0F0` 任意字回读 / `0x0F4` 字数+蓄水池 / `0x0F8` 提交次数）后，
同一次操作的对照是决定性的：

| 写法（同一笔 32 位写 0x0D4） | AXI 提交次数 | 结果 |
|---|---|---|
| Python `struct.pack_into("<I")` | **3** | FIFO 进 3 份 → 每 4 像素里 2 个是 0 |
| Python `m[o:o+4] = b"…"` | 2 | 错位 |
| Python `ctypes.c_uint32(...).value=` | **1** | 正确 |
| C `*(volatile uint32_t*)p = v` | **1** | 正确，**7.8~9.0 M 字/秒** |

`feed_pl.py` 原来整条喂数路径都用 `struct.pack_into` —— 这才是"帧自洽但判不出墙"的
根因（RTL 与 AXI 通路自始至终是好的：C 单笔写让 `mem[i]` 与推入值逐字一致）。
修完 `bytes=691200`（正好一帧）、`n_obs=8 n_gaps=4`、帧体与参考一致。

### 8) 顺手修掉的三个真 bug（都只在真硅/真数据上暴露）

1. `feed_pl.c` 的 `MAGIC_LE` 写成 `0x32485642`（`'2'`）—— 应为 `0x31564842`（`'1'`），
   于是它永远报 `crc MISMATCH`（帧其实是对的）。
2. `feed_pl.c` 用 `fwrite/memcpy` **直接读 /dev/mem 映射** → 设备内存上的宽/非对齐读
   触发 **SIGBUS**（rc=135）。改成逐字节拷到普通内存再算 CRC/dump。
3. 两个喂数器都把 **尾部 overflow 当失败**。实际是"帧已取满 230400 像素之后剩下的字
   灌满 FIFO"，帧完整性由 magic/长度/CRC 判 —— 320 帧里有 91 帧被这条规则误判，
   其实逐字节一致。

## 🎯 round 8：L2 接线（相机 → 正射 → PL → vt.jsonl）与**相机域口径**问题（2026-10-25）

### 做了什么

新增 `core/board/tools/pl_vision.cpp`：与 `vt_sparse` **接口完全一致**（stdin 640×480
RGB24、`--quad-file`、`--jsonl`），内部：

1. 用 `field_frame::homography()`（相机→场地）的 `invert` 做**页面→相机**正向采样
   （⚠ 方向搞反过一次：能出图、能出角色，但墙位置差一大截）；
2. 页面（640×480）按 **0.75 等比放进 640×360**（左右各 80 px 边带，语料就是这个摆法；
   若让四角铺满整幅图，白框压到图像边缘会被"离边 10 px 不算白框"剔掉 → `bands=0`）；
3. 推像素用**单个 32 位 volatile 写**（`struct.pack_into` 一次 store 会变 3 笔，见 round 7）；
4. 读回几何帧 → 换回页面坐标 `x=(x_pl-80)/0.75`、`y=(360-y_pl)/0.75` → 写 vt.jsonl。

### 现场 A/B（同一帧、同一个 quad，锁定那轮的 quad）

| 量 | vt_sparse（CPU，自适应阈值） | pl_vision（PL，固定阈值） |
|---|---|---|
| 角色 | (327.0, 222.5) | **(327.4, 224.2)** ✓ 基本一致 |
| 墙 | y=435.6 gl342 gr446 / y=270.7 gl193 gr317 | **0 道**（`wall_rb=40` 默认） |
| 墙（`wall_rb=0`） | 同上 | **y=434.9** ✓、缺口区间与第二道墙仍不符 |

→ **坐标/接线是对的**（角色与其中一道墙的 y 都在 1 px 内），差的是**判据在相机域不成立**。

### 根因（有数字）

墙在页面里渲染成暖白 (255,240,200)（R−B=+55），但相机拍出来是**中性偏蓝**：

| 相机 saturation | 墙像素 R−B |
|---|---|
| 16（锁定值） | **−5** |
| 32 | −11 |
| 64 | −20 |
| 100 | −37 |

场地底色 R−B≈−7。**提高饱和度只会把墙推得更蓝**，所以"调相机"这条路不通；
CPU 路径能用是因为 `vt_sparse` 用**亮度**自适应判据，不看颜色。

### 待决：PL 的判墙口径

1. **（建议）按相机域标定 PL 的 21 个配置寄存器**：以 C 参考为 oracle，用真实相机帧
   把 `wall_rb`/`band_*`/`min_gap_px`/`player_*` 等重新定到 640×360+相机噪声下，
   并保持 **PL == C 参考**（同一套参数）：判据本身的语义不变，只换数值。
   `pl_vision` 已支持 `--pl-param NAME=VALUE` 直接写配置寄存器，不需要重出位流。
2. 把 PL 的墙判据改成**亮度判据**（与 CPU 同口径）：要改 `vision_top` 的 classify
   + 参考实现同步 + 重出位流，工作量最大，但和 `vt_sparse` 真正同源。
3. 暂不接闭环，先把 1 做完再说。

### 平台状态（T0）

本轮为取帧临时起过 `platform_host.py`（渲染 + 查看器，`--max-seconds 150` 已自行退出）；
上一轮遗留的 3 个 `page_display.py` **不响应 SIGTERM**（R5 不许 -9），相机看到的是暗屏，
说明它们的窗口不在屏上、不挡页面。


## 🎯 round 9：L2 接线的实测对齐（2026-10-25，目标：PL 结果 = 基线）

### 已经拿下的

| 项 | 状态 |
|---|---|
| `pl_vision`（相机→正射→PL→vt.jsonl） | 与 `vt_sparse` 同接口，可跑 |
| 几何方向 | `field_frame::homography()` 是**相机→页面**，取 `invert` 才是页面→相机（踩过） |
| 正射摆放 | 页面按 0.75 等比放进 640×360（左右 80 px 边带），与语料一致 |

### 剩下的（都有明确现象）

### 顺带修掉的坑

- `pl_vision` 原来只写 `--pl-param` 覆盖项 → PL 的配置寄存器会粘住上一次的值，

  只能在输出阶段按"离页面上下沿 6 px 不算墙"过滤。


### round 9 续：相机域适配按"形状"重建，11/13 道墙对上（2026-10-25）

实测把三个坑逐个排掉：

1. **墙/角色不能按亮度分**：墙 ≈198、角色 ≈200~255、场地中位 26~32（p90 70~80，
   个别帧 p99 到 178）。按亮度分档两头都错（角色被当墙 / 墙被当角色）。
   → 改成**按形状**：每行找亮像素连续段，长度 ≥40 px 的段判为墙（墙是长水平条），
   其余亮像素抬到 210 并保持中性（角色 = bright）。
2. **阈值 40 → 150**：场地 p90≈80，40 会把大片场地染成墙；f1/f2 曾因此整幅变成
   一堵满宽墙（障碍 hw=320、缺口 0 个）。
3. **缺口→墙的 y 归属**：按"缺口左右边界与墙段 x 范围的距离"选，平手时取**更薄**的
   那条（墙 hh≈7，反光胖块 hh≈57），并排除贴页面上下沿的白框（它是细带，会把 y 带歪）。
