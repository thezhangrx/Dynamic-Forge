# 块设计：PS7 + AXI 互联 + vision_axi

> 这份记录**为什么非要有块设计**、它长什么样、以及一路踩过的 7 个坑。
> 产物：`bd_vision.bit`（2026-10-14 首次跑通）。

---

## 1. 为什么非要有它

`vision_axi` 的 **135 个端口**（AXI-Lite 从口 + `din_*` 视频输入）在真实部署里
**来自 PS7，不是外部引脚**。所以裸模块出不了比特流：

```
ERROR: [DRC NSTD-1] 135 out of 135 logical ports 无 IOSTANDARD
ERROR: [DRC UCIO-1] 135 out of 135 logical ports 无 LOC
```

把这两条降级成 Warning 能骗出比特流，但那等于让 FPGA 去驱动 135 个电平未定义的
引脚 —— **可能烧板**。正路是**把 PS7 例化进设计**，让那 135 个端口变成内部连接。
外部只剩 PS 自己的 DDR/MIO —— **专用引脚，由 PS7 自动约束** —— DRC 自然通过。

而且这才是"**CPU/FPGA 异构部署**"的真实形态：PS 跑 Linux（读相机、跑决策），
PL 跑视觉流水线，两者用 AXI 说话。

## 2. 结构

```
    PS7（硬核，跑 Linux）
     ├─ FCLK_CLK0 = 50 MHz ──┬──────────────► 所有模块时钟
     │                       └─ proc_sys_reset ─► 同步复位
     └─ M_AXI_GP0 ──► AXI 互联 ──► vision_axi_ip.s   （AXI-Lite 从口）
                                              ▲
                            tpg_source ───────┘ din_*（像素）
```

**像素源先用片上图案发生器**（`rtl_bd/tpg_source.v`，复用协同仿真里那个
`vision_tpg`）。理由：它的几何是**手算得出来的**，所以 PS 一能读回几何帧，
立刻就能判断真硅上这条链对不对 —— 不需要相机、不需要标定。
等这条通了，再把 `tpg_source` 换成"PS 送帧"或"相机"，**每次只动一个变量**。

`vision_axi_ip`（`rtl_bd/vision_axi_ip.v`）只是**按 AXI 约定改了时钟/复位名**
（`clk`→`s_axi_aclk`、`aresetn`→`s_axi_aresetn`），好让 `ipx::infer_bus_interfaces`
认出总线接口。**内部是原封不动的 `vision_axi`**，功能一个字节没改 ——
"为了接进块设计而改被验证过的 RTL"是不可接受的。

## 4. 一路踩过的 7 个坑（都值得记住）

| # | 现象 | 原因 / 解法 |
|---|---|---|
| 1 | `create_ip` + `synth_design`（**in-memory** 项目）报 `Synth 8-439 module 'ila_0' not found` | in-memory 项目里生成的 IP 进不了综合；要用**落盘真项目** |
| 2 | 综合后插 `create_debug_core` 报 `Vivado 12-711 exceeds the maximum '1' allowed debug ports` | 2018.3 的 `debug_core` 上**没有** `C_NUM_OF_PROBES`（`12-4444`） |
| 3 | 位流能出但板上找不到 ILA（`Labtools 27-3361 debug hub core was not detected`） | **dbg_hub 的插入是 Runs 流程做的**；直接调 `opt_design/place/route` 不会插 |
| 4 | `BD 41-758 ... /ps7_0/M_AXI_GP0_ACLK ... not connected` | PS7 **自己那些 AXI 端口的时钟**也要驱动（漏了整排 6 个） |
| 5 | `BD 41-237 FREQ_HZ does not match: /vision_0/s(100000000) vs M_AXI(50000000)` | 打包出的 IP 默认声明 100 MHz；在 BD 侧 `set_property CONFIG.FREQ_HZ 50000000` 对齐（**不改时钟** —— 50 MHz 是时序验过的） |
| 6 | `CRITICAL WARNING BD 41-1348 Reset pin ... connected to asynchronous reset source` | `FCLK_RESET0_N` 是异步的；过一级 **`proc_sys_reset`** 产生同步复位（每个 Zynq 块设计都这么干） |
| 7 | `make_wrapper` 产出的 wrapper **一个端口都没有** → PS 拿不到 DDR | 要显式 `make_bd_intf_pins_external [get_bd_intf_pins ps7_0/DDR]`（FIXED_IO 同理）。厂商的 `ps_ai_wrapper.sv` 里是有这些端口的 |

另外两个小的：
* `report_bd_address` 是**更新版本**才有的命令，2018.3 里没有（`invalid command name`）；
* `make_wrapper` 把 wrapper 写在 **`.srcs`** 下，不是 `.gen`；glob 写死 `.gen` 会 `no files matched`。

## 5. 怎么跑

```bash
# ① 先把 vision_axi_ip 打包成 IP（约 2.5 分钟）
cd /mnt/d/FPGAWORKS/vivado_impl
cmd.exe /c "D:\\Vivado\\Vivado\\2018.3\\bin\\vivado.bat -mode batch \\
  -source D:\\FPGAWORKS\\vivado_impl\\bd_pack.tcl \\
  -tclargs D:/FPGAWORKS/vivado_impl/rtl D:/FPGAWORKS/vivado_impl/rtl_bd \\
           D:/FPGAWORKS/vivado_impl"

# ② 建块设计 + 综合 + 实现 + 位流（约 45 分钟）
cmd.exe /c "D:\\Vivado\\Vivado\\2018.3\\bin\\vivado.bat -mode batch \\
  -source D:\\FPGAWORKS\\vivado_impl\\bd_vision.tcl \\
  -tclargs D:/FPGAWORKS/vivado_impl/rtl D:/FPGAWORKS/vivado_impl/rtl_bd \\
           D:/FPGAWORKS/vivado_impl bd_vision"
```
