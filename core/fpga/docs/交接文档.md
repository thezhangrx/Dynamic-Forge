## 3. 不能破坏的契约

这些改动**不会让编译失败**，只会让结果全错 —— 所以每条都有测试钉住。

| 契约 | 权威定义 | 守卫 |
|---|---|---|
| 线协议（magic/版本/记录字节数/flags 位号/编码表/定标 Q=64） | `core/standard/vision/vision_frame.py: describe_vision_protocol()` | `test_rtl_contract.py` 7 项 |
| 定点 arctan 表（9 点） | Python `atan` 真值 | 逐项核对（RTL↔C↔真值） |
| `EDGE_AVG == 2` | RTL 的"持续台阶"是**两级移位寄存器**（结构） | 跨语言核对 |
| 检测参数默认值（21 项） | `core/vision/wall_with_gap.py: WallWithGapParams` | Python ↔ C ↔ RTL 复位值**三方核对** |
| 配置寄存器地址映射（0..20 + 31） | `core/fpga/rtl/vision_top.v` 的 `CFG_*` | RTL ↔ AXI 协同仿真 tb 逐项核对 |
| AXI 地址映射（0x000/0x080/0x0C0/0x100…） | `core/fpga/rtl/vision_axi.v` 头部注释 | RTL ↔ tb 逐项核对 |

**最重要的一条是"参数默认值三方一致"**。它是补上的，而且它本该早点存在：
曾经 C 模型与 RTL 把墙的 G 下限写成 110（Python 是 60）、亮色少了
`max-min < bright_spread` 这条、绿色写成 50/90（Python 是 10/90）。
三处都偏了，而 **"RTL == C 模型" 全程全绿 —— 因为两边错得一模一样**。
症状是 P1 对账里"缺口 Python 160 / C 159、墙段 320 / C 318"，当时被当成
"连通域语义的正常差异"。修完之后 P1 变成 160/160、320/320，
缺口中心误差 max 从 0.16 px 降到 **0.00**。

> **教训（两位一定要记住）**：`RTL == C 模型` 只能证明"两边一样"，不能证明
> "两边都对"。**只有 Python 那一层是语义真值**。任何新算子，都要有一条
> "RTL/C 的默认参数与 Python 逐项相等"的测试，否则两层可以一起错。

## 4. 参数要**按分辨率缩放**（上板必读）

Python 的 `WallWithGapParams.rescaled(w, h)` 会按分辨率缩放**长度/面积**类参数。
默认值是给 640×480 调的；我们的录像是 640×360 → `s = 0.75`：

| 参数 | 640×480 默认 | 640×360 实际 |
|---|---|---|
| `field_col_min` | 5 | **4** |
| `band_join_rows` | 4 | **3** |
| `band_min_rows` | 5 | **4** |
| `min_seg_px` | 8 | **6** |
| `min_gap_px` | 8 | **6** |
| `player_min_area` | 60 | **34** |
| `player_max_area` | 1500 | **844** |
| `wall_col_min` / `edge_avg` | 2 / 2 | 2 / 2（不变） |

阈值类（`wall_rb`/`wall_min_r`/`wall_min_g`/`bright_min`/`bright_spread`/
`green_gm`/`green_min`）和比例类（`band_row_pct`/`wall_col_pct`）**不缩放**。

**RTL 的 21 个配置寄存器就是为了这件事**：PS 必须自己算好缩放后的参数，
在启动每一帧之前写进寄存器。**不缩放会错，缩放两次也会错** ——
两种都踩过：

* 不缩放 → 差 2 条墙段 / 1 个缺口（一帧里）；
* 缩放两次（`0.75² = 0.5625`，`band_min_rows` 变成 3）→ 多出半条墙带。

`compare_with_python.py` 现在有一条守卫：把 `detect()` 实际用的参数
（`diagnostics["params"]`）与喂给 C 的参数逐项比，做错 0 次或 2 次都会当场报错。

> ⚠ **`edge_avg` 是结构参数**：RTL 的持续台阶固定 k=2（两级移位寄存器），
> 运行时改不了。640×360 缩放后正好是 2，所以没事；换成别的分辨率如果
> 缩放后不是 2，**RTL 与 Python 就不可比** —— 要么改 RTL，要么换分辨率。

## 5. 两条并行的活

下面是我建议的分工。**可以调** —— 但建议保持"一个人碰板子、一个人碰数据"，
因为上板那段有大量等待（综合、烧写），另一条线可以并行推进。

### A 线：上板（PL/PS 通路）

**第一个任务：在 Vivado 2018.3 里把 `vision_selftest` 综合出来**

| | |
|---|---|
| 输入 | `core/fpga/rtl/vision_selftest.v` + `vision_tpg.v` + `vision_top.v` + `vision_ccl.v` |
| 器件 | `xc7z030ffg676-2`（对标 JFMQL30TAI676H），Vivado 2018.3 + `JFM_Kits` 时序库补丁 |
| 做法 | 新建工程 → 加 4 个 `.v` → top 设为 `vision_selftest` → 加一个 50/100 MHz 时钟和复位 → `auto_run=1` → 综合 → 实现 → 生成 bitstream |
| **验收 1** | `report_utilization` 有数：LUT / FF / BRAM / DSP。**重点看 `vision_ccl.v` 的标签表（256×~150 bit ≈ 37 kbit）被推成 BRAM 还是寄存器阵列**，以及 `vo_scale_round` / `vo_atan2_q6` 里的 `/` 被推成什么规模的除法器 |
| **验收 2** | `report_timing_summary` 在最坏路径上收敛（WNS ≥ 0）。做不到就先报出最坏路径是哪一段 |
| **验收 3** | JTAG 烧进去后，用 ILA 或把调试口接到 LED/寄存器上，8 个场景的 `frame_done` 都要出，帧长都是 184 字节 |

**第二个任务：PS 侧驱动 + AXI 通路**

用 `vision_axi` 换掉自检顶，PS（Linux 或裸机）按下面这套地址访问：

| 地址 | 作用 |
|---|---|
| `0x000 + 4*i` (i=0..20) | 配置寄存器（**写缩放后的参数**，见 §4） |
| `0x080` / `0x084` | 调试口：写 `{sub,idx,sel}`，读数据 |
| `0x0C0` | 读：`bit0` busy、`bit1` 上一帧完成、`[23:8]` 帧计数、`bit24` 窗口溢出；写 `bit0=1` 启动一帧 |
| `0x0C4` / `0x0C8` / `0x0CC` | `seq` / `stamp_ns` 低 / 高 |
| `0x0D0` | 上一帧字节数 |
| `0x100 + 4*j` | 几何帧字节窗口（小端） |

**验收**：PS 读出 8 个场景的几何帧，用 `core/standard/vision/vision_frame.py` 的
`decode_vision_frame()` 解出来，字段与 §2 表格里的自检期望值一致。

> ⚠ **不会撕裂**是建立在"一次 `frame_start` 只跑一帧"之上的。改成连续采集
> 就要双缓冲或上 DMA。

**第三个任务：相机通路**
USB / SDI / MIPI 三选一（见 `core/fpga/docs/移植规划.md` §7.1）。
像素输入必须与 `vision_axi` 的 `clk` **同步** —— 相机像素时钟不同源时，
跨时钟域 FIFO 在外层（`vision_axi` 是单时钟设计，**没有假装自己有 CDC**）。

### B 线：现实验证与闭环

**第一个任务：把 Python 那一层的对账跑实**

```bash
python vision_capture_rig.py --out data/vision/run5          # 开平台 + 录制 + 出报告
python vision_reconcile.py --run data/vision/run5            # 单独出报告
```

| | |
|---|---|
| 验收 | 时间偏移（δ）稳定、IDF1 达标、缺口中心误差 ≤0.1 场地单位 |
| 为什么先做这个 | 上板之后要拿 PL 的结果跟 Python 比。**Python 那层自己都不稳，就没法判断 PL 对不对** |

**第二个任务：相机的颜色标定**

`vision_check.py` 已经证明了一件事：真实拍摄下**颜色会被截顶**——

甚至 `(255,255,255)`（`R-B = 0`），于是墙 0% 检出。
`core/vision/adaptive.py` 是那条自适应链，但**还没接到板上**。

| | |
|---|---|
| 验收 | 固定光照下，墙掩膜与平台真值的 IoU ≥ 0.8；换一档曝光仍然可用 |
| 产出 | 一组"曝光档位 → 21 个配置寄存器值"的表，直接给 A 线用 |

## 6. 已知的坑（都是真踩过的）

按"再踩一次的代价"排序：

1. **两层一起错，没人发现。** 见 §3 末尾。任何新算子都要有"跟 Python 逐项对"的测试。
2. **参数缩放做了 0 次或 2 次。** 见 §4。症状是"算法不一致"，实际是参数不一致。
3. **Verilator：函数调用别直接写进"数组元素"的非阻塞赋值 RHS。**
   实测 `obs_words[n*9+8] <= vo_atan2_q6(a,b);`（同一函数在 `$display` 里也调了一次）
   落库的值和打印出来的值不一样，**中间量全对、只有存进数组的字节错**。
   提到一根组合 wire 上再赋就对了。
4. **`seg_limit` 提前 +1 会吐假段。** `seg_push` 只在"段长 ≥ `min_seg_px`"时
   才真的加一。早先写成 `seg_limit <= run_in ? n_segs + 1 : n_segs`，于是
   "最后一段比 `min_seg_px` 还短"时多出一条 `x=[0,0]`、`ln=0` 的越界段，
   `n_obs` 和帧长都跟着错。修法是多一拍、用已提交的 `n_segs` 结算。
5. **`dout_last` 每帧拉高两次。** 早先写成"payload 最后一字节 **或** CRC 最后一字节"。
   纯字节流看不出来（消费方只数 `dout_vld`），但 AXI 包装层拿它定帧长会算成 4 字节。
   **`tb_vision` 跑了 320 帧零差异都没发现它** —— 是走 AXI 路径的 `tb_axi` 抓到的。
6. **`#ifndef VR_NO_MAIN` 必须包住 `main` 和 `load_image`**，否则链进 Verilator 时
   `multiple definition of main`；漏包 `load_image` 则 `-Wall -Wextra` 报 unused。
7. **给 Verilator 自带 `main` 的 tb 时不能用 `--binary`**（会再生成一个 main）。
   用 `--cc --exe --build`。
8. **`VERILATOR_ROOT` 必须导出**，否则去 `/usr/share/verilator` 找 `verilated_std.sv`
   报 "Cannot find verilated_std.sv"。
9. **C 侧对象要单独用 gcc 编**：Verilator 会把 `.c` 当 C++ 编，而且 `-CFLAGS` 里的
   `-DFOO` 传不到它。`cosim/Makefile` 里 `$(REF_OBJ)` 单独一条规则就是为这个。
10. **Verilator 的 lint 注释里 "verilator" 不能是注释的第一个词**，
    否则被当成指令报 "Unknown verilator comment"。

## 7. 还没做的 / 已知缺口（**别当成已经解决了**）

| 缺口 | 影响 |
|---|---|
| **一次都没综合过** | 资源/时序全未知。标签表、除法器、`frame_mem` 的字节写是三个风险点 |
| **没有 CDC** | `vision_axi` 单时钟；相机像素时钟要另加异步 FIFO |
| **AXI 读写串行化** | 接 DMA / 多主机要改成真正的双通道 |
| **帧窗口无缓冲** | 只能"启动一帧→等完成→读"，不能连续采集 |
| **`edge_avg` 固定 2** | 换分辨率若缩放后不是 2，RTL 与 Python 不可比 |
| **相机前端没写** | 只有"像素流进"的接口；Bayer 去马赛克 / YUV 转换没有 |
| **自适应曝光/白平衡没接** | Python 侧有（`core/vision/adaptive.py`），RTL 侧只有固定阈值 |
| **上限边界没测** | 620 帧语料里标签表最多用 3 项、障碍最多 17 条。`MAX_LABELS=256` / `MAX_OBS=32` / `MAX_GAPS=16` 这些上限**本身没被触发过** |
| **自检图案只覆盖理想输入** | 无噪声、无抗锯齿、无光照变化。证明"通路对"，**不能替代真实录像的逐位对账** |
| **角色估计器差异未决** | Python `refine_circle` vs RTL 矩质心，0.33~3.17 px。**要决定以谁为准** |
| **`decision/` 已删、`core/cpu` 与 `bullet_sim/cpu` 有重复** | 与本次交接无关，但两位如果碰到 CPU 那一层会看到 |
