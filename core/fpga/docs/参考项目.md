## 1. `docs/repo/bitstream/projf-explore` —— Project F ✅ 参考

| | |
|---|---|
| 是什么 | Will Green 的 FPGA 教学项目（约 50 篇博客 + 可跑设计），涵盖 FPGA 图形、内存、FSM、跨时钟域 |
| 许可 | **MIT**（`LICENSE`：Copyright (c) 2023 Will Green, Project F） |
| 可不可以抄代码 | **MIT 允许**，但本项目仍**自己写**，只借鉴结构 |
| 用到了什么 | 见下面 §3 |

最关键的一份：`lib/memory/bram_sdp.sv`（简单双口 BRAM）。**它印证了本项目改动所依赖的那条规则**：
BRAM 只能同步读 —— 写入用 `always_ff` 带使能，读出用 `always_ff` 直接寄存。它本身
**连 `ram_style` 都不用**；本项目之所以加，是因为还有 **1-bit 宽的掩膜数组**，
需要显式强制落 BRAM（实测见 `工具链现状.md`）。

`demos/life-on-screen/lib/display/framebuffer_bram.sv` 还示范了**BRAM 延迟的记账方式**：

```systemverilog
localparam LAT = 3;   // BRAM、地址计算、CLUT 三级延迟
lb_en_in_sr <= {lb_en_in, lb_en_in_sr[LAT-1:1]};
if (lb_en_in_sr == 3'b100) busy <= 0;   // 读完成：对齐延迟
```

即**用移位寄存器把控制信号延迟到与数据同拍**。本项目**没有采用这种做法**，
理由见 §4 —— 但这是理解了它才知道该不该用的。

## 3. `https://zipcpu.com/` —— ZipCPU 博客（Dan Gisselquist）📖 方法论参考

**只是博客文章（教学散文），不是拿它的 RTL 来抄。** ZipCPU 的 RTL 仓库是 **GPLv3**，
按本项目的纪律**绝不复制**。

用到的两篇：

| 文章 | 提供了什么 |
|---|---|
| [Strategies for pipelining logic](https://zipcpu.com/blog/2017/08/14/strategies-for-pipelining.html) | pipeline 信号的**分类学**：global CE / traveling CE / simple handshake / buffered handshake |
| [Building a prefetch module](https://zipcpu.com/zipcpu/2017/11/18/wb-prefetch.html) | **prefetch（预读）** 这个手法本身 |

那篇分类学文章里有一句正好描述本项目遇到的问题：

> *The difficult part of a digital logic pipeline is that the pipeline runs and
> produces outputs even when the inputs to the pipeline are not (yet) valid.*

**BRAM 就是一拍延迟的流水**，读回来的数据比地址晚一拍 —— 这就是整件事的根源。

## 4. 这些参考**怎么影响**了本项目的改法

本项目的扫描器（行带扫描 `S_SPAN`、列扫描 `S_COL_SCAN`、CCL）是**固定速率流水**：
每拍一个像素、不会 stall、不需要反压。按上面那篇分类学，它属于 **global/traveling CE** 一类，
**不需要** handshake。

改法有两条路：

| 路 | 做法 | 评价 |
|---|---|---|
| **A. 延迟消费端** | Project F 的做法：给每个控制/索引信号配移位寄存器，延迟到与数据同拍 | 通用，但要动状态机的**每一处**索引与判定 |
| **B. 预读地址（本项目采用）** | ZipCPU prefetch 的思路：把"下一拍的地址"提前一拍喂给 BRAM | **数据与状态机逐拍对齐，状态机一行不用改** |

**选 B 的理由不是它更高级，而是本项目的硬约束**：`core/fpga/` 有一份
**620 帧、4.3 亿次比对、逐位一致**的基线（`Vvision_top` ↔ C 参考模型）。
改法 A 要改状态机的时序，一旦有一处漏了就静默出错；改法 B 让
`gray_rd(t) = gray_mem[rd_nxt(t-1)] = gray_mem[rd_addr(t)]`
—— **与原来的异步读逐拍等价**，改动面小得多。

代价：`rd_nxt` 必须与状态机对 `rd_addr` 的赋值**逐字一致**（6 处）。这条由那 620 帧守着。

## 5. 一句话总结

* **Project F（MIT）**：确认了"同步读 → BRAM"的标准写法，也看到了延迟记账的通用做法。
* **ZipCPU 博客**：给了 pipeline 信号分类，确认"预读地址"是正经手法而不是偏方。
* **Hammer（BSD）**：无关，别当 Verilog 参考。
* **代码一律自己写**，只借鉴结构；GPL 的 ZipCPU RTL 一个字都不抄。
