# 板载视觉大翻修 —— 目标、约束与退出条件

> 这份文件是**修改期间的唯一口径**。每次动视觉相关代码前先读它；每次改动后把
> "改了什么 / 数字怎么变"记进最后一节。结论必须以本文件的测量协议产出，
> **不接受"看起来对了"**。

## 0. 为什么翻修

静态墙/缺口已经验证可用（10/10 帧、缺口中心误差 1 px、0.6 ms/帧），但整套视觉
**没有建立可靠的场地坐标系，也没有真正识别到角色**。12.4 fps 只证明吞吐达标，
不证明导航闭环可靠。翻修的目标不是换更高级的算法，而是**把已有技术用对**：

1. 几何来源选错了（用亮度台阶量到了显示器边框，纵向尺度还是假设的）；
2. 搜索域没有约束（全图找连通域 → 把 UI 当墙、把定位标记当角色）；
3. 光度没有归一化（相机自动曝光第 3~4 帧整体 +50%，所有绝对阈值翻面）；
4. 有一段算力被算完丢掉（structural 模式下 RTL 结果被 `rects.clear()` 丢弃，
   但每帧仍付 33 ms 推像素 + 等流水线）。

## 3. 任务与退出条件

### P0 测量骨架（先做，纯增量，不动算法）
- `--diag-log <path>`：每帧一条 JSON（字段见 §4）。
- 仿真侧 `--collision-log <path>`：每帧最小间距 + 碰撞事件计数。
- 耗时统计：各阶段 p50/p95/p99/max，不只平均值。
- **退出条件**：一条命令产出 `diag.jsonl` + 汇总表（INVALID 帧数、角色有效帧数、碰撞次数、耗时分位）。

### P1 几何：四标记单应为主，`field_extent` 降为兜底
- 唯一几何来源：`MarkerCache.homo`（4 点 DLT）→ `field_bbox` 给 `scale_x/scale_y`。
- `field_extent` 只在无单应时兜底，且**最长 150 ms**；超时即 `INVALID`。
- `INVALID` 时 `stay`，不沿用任何缓存坐标，`stop_reason` 必须可区分。
- **退出条件**：`field_valid` 率、`scale` 稳定性、四边形宽高比误差有统计；新增四类测试集
  （部分遮挡 / 窗口化 / UI 干扰 / 低分辨率）；`INVALID` 帧移动指令 = 0（断言）。

### P2 角色：与标记解耦，只在场地 ROI 内找
- 候选生成：场地矩形（单应反投影）内的亮连通域；先排除四标记邻域。
- 评分：面积 + 圆度 + fill + **环状结构判据（深底亮内 vs 纯亮圆）** + 与上一帧的连续性。
- 缺失/歧义 → `INVALID`，**不允许**用标记坐标顶替。
- **退出条件**：precision / recall / 漏检率 / 定位误差（px 与场地单位）四组数字，附失败样例。

### P3 选墙：按"角色前向威胁"选，并做单元测试
- 定义：角色前向距离最小且缺口可达的那道墙为"当前威胁墙"；保持跨帧 ID 与迟滞。
- 每帧输出 `selected_wall_id / 相对位置 / 选择理由 / 缺口中心`。
- **退出条件**：单墙、双墙、上下顺序互换、多缺口、跨帧关联 5 组单元测试全过。
- ⚠ 已知：`wall_gap.hpp::pick_nearest_wall` 用 `h - cy` 排序是**反的**（选中最上面那道）；
  生产路径（`main.cpp` 门选择用 `|wy - player.y|` + `door_locked` 迟滞）是对的，
  修的时候别把已验证的那段改坏。

### 之后（不阻塞前三项）
- 光度归一化（以场地中位数为参考）→ 阈值免疫 AE 跳变。
- PL 去留：给 ROI 提议（推荐）或停推像素（省 33 ms）。
- 输入采样率：720p + 面积下采样，或让场地占满画面。
- 亚像素标记中心。

`coordinate_error` 只在有独立真值时填写（真值来自仿真状态或人工标注，**不得**用算法输出）。

## 5. 测量协议（不遵守的结论不算）

1. 对照组必须同批帧、同相机设置、同场景种子。
2. 时间对齐：用墙的 y（单调）做锚点求单一时间偏移；**被用来对齐的量不参与误差统计**。
3. 分母不许静默删帧：无效帧单独计数并报出来。
4. 每个结论附复现命令 + 前后数字；失败用例必须留下。
5. 视频/截图只能作辅助证据，不能替代统计。
6. **坐标约定**：仿真真值 / `@STATE` 的 y 轴**朝上**，而 `rectify::contract_markers()`
   定义的场地坐标 y **朝下**（TL 是 `(32,32)`）。换算时要做 `y -> field_h - y`。
   不翻的话"期望像素"会跑到画面另一头（实测偏 173 px），看起来像检测偏了，其实是量尺错了。
7. **构建纪律**：改了任何 header 都必须**整目录同步再重建**（`core/board/tools/sync_board.sh`）。
   实测踩过：只传了 `main.cpp` + 两个新 header，漏传 `geometry.hpp`，板子编译照样通过，
   运行时却每帧判 `marker_far_from_corner`（旧的角点顺序），看起来像算法坏了。

所以在线那 40 单位里，检测（离线验证 10 px）只占小头，其余是**时间对齐残差**。
下一步应把"帧交付时刻"也写进诊断（`host_t` 目前是处理时刻），让在线对账与离线同口径。

### 10.2 闭环下仍然错的那一类：**墙的端头**

**检测落在墙段的左端头上** —— 那是 ~15×10 px 的亮块，在面积、填充率、圆度、横向亮段上
和角色圆盘**几乎完全一样**。

已加的第一道约束：`player::find` 接受"已知墙带行区间"，候选中心落在墙带（±4 px）内就排除。
这解决了部分（+2.7%），但闭环里仍有大量错帧 —— 因为端头常常落在墙带**边缘之外**几像素。

### 10.3 下一步（明确）

1. **端头判别**：用墙段的 x 跨度（不只是行区间）判"候选是否贴着某段墙的端点"；
   角色与墙端头唯一的物理差别是**上下文**（端头必与一段长亮条相连）。
2. 或者：把"角色"的候选限制在"墙带之间的通道里"（角色只可能在缺口内侧/通道中）。

## 11. 虚拟平台真值服务（影子模式）

用户提出的架构：**在"视觉"与"决策"之间插一层状态估计** —— 平台/障碍的位置由**自己的
指令积分**推进（`p += DISCRETE_DIRECTIONS[action] × 平台速度 × Δt`），视觉只在"看得清"
时做**慢校正**；板子应当读这层的 `@STATE`，而不是每帧识别结果。
诊断出的问题一律往**视觉**修（决策层已验证，不动）。

已实现 `core/board/tools/virt_truth.py`（影子模式：只算、只记、不参与控制）：

| 能力 | 说明 |
|---|---|
| 指令积分 | 动作码 → 单位方向 × 平台速度；速度**从真值标定**（实测 **158.7 场地单位/秒**）|
| 视觉慢校正 | α=0.25，且**只在地理可信（`geo_why=ok`）且角色有效时** |
| **离群门** | 观测与模型差 > `--gate`（默认 60 单位）就**不采信**（10% 帧被拒） |
| 障碍模型 | 每道墙 `(y, gap)` 各自积分 + 速度慢估（α=0.3），过期自动丢弃 |
| **逐帧日志** | `virt.jsonl`：`t / action / pred / vision / virt / resid / walls[] / truth`，可直接与仿真真值对账 |
| 对账表 | `--table N` 打印"模型 / 视觉 / 真值 / 两个误差"并排表；汇总给 p50/p95、帧间抖动、残差均值（有偏会立刻看出来） |

实测（607 帧、平台在动、速度标定 158.7）：

| 指标 | 纯视觉 | 虚拟真值 |
|---|---|---|
| 角色误差 p50 / p95 | 35 / 159 | **37 / 159** |
| **帧间抖动 p95** | 36.0 | **16.2**（↓2.2×） |
| 视觉离群帧 | —— | 拒掉 **10%** |
| 最长连续无观测 | 25 帧（1.5 s） | 靠积分**继续输出** |

结论：这一层把**抖动**和**断流**解决了（这正是"左右乱晃"的来源之一），但**精度上限仍是视觉的**
——所以按用户的要求，问题继续往视觉修。

### 11.1 "识别到什么程度才算稳定"（可判定的标准）

由决策需求反推，不是拍脑袋：

| 量 | 门槛 | 依据 |
|---|---|---|
| 角色横向偏差 p95 | **≤ 20 场地单位** | 缺口半宽 − 角色半径 ≈ 35 − 10 = 25；留余量取 20 |
| 缺口中心偏差 p95 | **≤ 20 场地单位** | 同上（横向可用宽度） |
| 墙 y 偏差 p95 | **≤ 20 场地单位** | ≈ 0.15~0.3 s 时间误差（墙速 64~116/秒） |
| 平台速度标定误差 | **≤ 5%** | 开环 10 s 积分：5% × 158.7 × 10 ≈ 79 单位（已超预算） |
| 有效帧占比 / 最长空档 | **≥80% / ≤ 300 ms（约 6 帧）** | 预测窗上限 300 ms；实测最长 25 帧 → 目前不达标 |
| 帧间抖动 | **不作要求** | 由虚拟真值滤波吸收（实测抖动 p95 36 → 16） |

**当前**：视觉角色 p95 159、缺口 p95 约 300（另有 25 帧空档）→ **远未稳定**，不能切。
能切的判据就是上表全部满足——其中"抖动"那一行可以靠这一层补掉。

### 11.2 已经转成虚拟真值的障碍，还要不要再识别？

**要，但只用于三件事，而且不许用逐帧观测去改积分位置**（否则又会把抖动带回来）：

1. **存在性/新墙**：积分器不知道新墙出现。观测到"模型里没有的墙（y 差 >40 单位）"就新建。
2. **速度慢校正**：墙速与缺口扫速在场景里是**常量**，用观测残差慢估（α=0.3），
   这样长时间积分也不会漂。
3. **重初始化（只在持续不一致时）**：连续 **5 帧**残差 > **40 单位** → 判定模型错了，重置该墙。
   单帧残差大只当离群（和角色那条 `--gate` 同一条原则）。

对应到实现：`WallModel.correct()` 现在就是这样做的（预测→差分估速→α 混合），
以及 `walls` 列表里过期墙（预测 y 跑出场地）自动丢弃。


## 12. 时间窗鲁棒估计（"宁可要范围，不要不稳定的点值"）

用户口径：缺口中央的 x 会有微小摆动 → **取识别过程中的平均、丢掉离群值**；角色、墙的位置
同样处理。

### 12.1 实现

`core/board/robust.hpp`：时间窗（**按时间不按帧数**，因为帧率在 13~18 之间飘）+ 三种统计：

| 统计量 | 用途 |
|---|---|
| **中位数** | 最稳的"典型值"，离群值完全不影响 |
| **截尾均值**（先 MAD 剔离群，再去两端 20%） | 比中位数用更多信息，又不像普通均值被一个错块带跑 |
| **鲁棒范围** `lo()/hi()/spread()` | 给"大概范围"而不是假精确；`spread` 就是目标的不确定度 |

已接进板子：
- **角色**：像素坐标 0.35 s 窗 + 截尾均值 + MAD 剔除 → 喂给决策；`player_unc`
  （窗内两轴范围之和）进诊断日志；
- **缺口中心 / 墙 y**：在原有 α-β 平滑之外**再套一层**同样的鲁棒窗（缺口帧间跳变 p90 28 单位，
  而横向可用宽度只有 25 单位）。

### 12.2 实测效果（90 s 闭环跑）

| 指标 | 值 |
|---|---|
| **角色帧间跳变** | 中位 **7**、p90 **13**、**95% ≤20 场地单位** ← 稳定性达成 |
| 角色绝对误差 | 中位 52、**≤20 单位仅 23%** ← 精度未达成 |
| 缺口中心误差 | 中位 **11**、**≤20 单位 71%** |
| `player_unc` | 中位 18.5 px |
| 指令 vx 翻转 | 14 次 / 100 帧 |
| 碰撞 | 17 次 / 75 s |

**结论**：这一层把"抖"解决了（帧间跳变 95% ≤20 单位），但**绝对精度没变**——
因为它治的是抖动，治不了偏置和偶发错块。离线重放同一批数据也印证：鲁棒窗把
**视觉输入**的 p95 从 235 压到 **112~119**，但模型输出被"未标定的指令延迟/速度"拖累
（p50 45），所以目前**鲁棒视觉**比"积分模型"更可信。

### 12.3 结论与下一步

1. 时间窗鲁棒化：**保留并作为默认**（稳定性收益明确）。
2. 精度仍是视觉的事：角色 ≤20 单位 23% 的瓶颈是**偏置/偶发错块**（墙端头那一类），
   下一步继续在离线闭环语料上压这一类。
3. 虚拟真值的积分模型要先用实测**指令延迟**标定（启动阶段测得 0.457 s），否则积分
   永远比真实"跑在前面"，校正被离群门大量拒掉（实测 15%~28%）。
4. 缺口已经能给"范围"（`lo/hi/spread`），决策侧下一步可以用 `spread` 做门控：
   范围太宽时按"边走边看"而不是急打方向。

## 13. 对账口径修正 + 三个"被测系统以外"的真凶（2026-10-18 下午）

这一节把前 12 节的**精度数字全部作废重算**。原因不是算法改了，而是发现之前的
"视觉误差"里有三样**跟视觉无关**的东西被算进了视觉：时钟、仿真实时率、动作队列。
三项都实测过、都修了。修完之后同样的视觉代码，误差数字从"中位 52 单位"变成
"离轨迹中位 5.8 单位"。

### 13.1 真凶一：板子的系统时钟比主机慢 1.9 s，且**板子的时间基快 9%**

| 实测 | 值 | 方法 |
|---|---|---|
| 板子系统时钟 − 主机 | **−1.9 s**（会漂） | `ssh board date` vs `date`，连接复用后 RTT 20 ms |
| 板子 `CLOCK_MONOTONIC` 速率 | **1.09 板秒/真实秒** | 板子上 `sleep 20`，主机单调钟只走了 **18.35 s** |
| clocksource | 只有一个 `arch_sys_counter` | `/sys/devices/system/clocksource/...` |

后果：诊断日志里的 `host_t`（板子墙钟）拿去做配对，等于给每帧加 1.9 s 假延迟 ——
平台 166 单位/秒 → **300 单位**的假误差；板子上量到的"秒"都比真实秒短 9%，
所以按板秒算的速度自然比按真实秒算的**大 9%**（实测 155 vs 142）。

处置：
* `tools/sync_clock.sh` —— NTP 式的单次设定 + 复核（**必须走 ssh 连接复用**：
  不复用时每次 ssh 建会话要 0.3~1.5 s，中点估计误差有 0.8 s，迭代会来回震荡）；
* `tools/boot_cal.sh` 每次跑之前自动测速率并传给分析脚本；
* 对账工具 `tools/vision_accuracy.py` **不依赖墙钟**：按角色轨迹搜偏移量。

### 13.2 真凶二：仿真只有 **0.75 倍实时**，所以墙钟对齐会把运动算成误差

仿真 `--state-log` 里同时有 `t`（仿真时间）和 `unix`（墙钟）。实测
49.7 仿真秒 / 66.3 墙钟秒 = **rtf 0.75**（负载高时会掉到 0.48，并有 2.9 s 的
周期性卡顿，实测每隔 ~35 s 一次）。所以"按墙钟同一时刻配对"本身就不成立，
必须用真值自己的 `(unix → t)` 表插值；`vision_accuracy.py` 就是这么做的。

### 13.3 真凶三（**修了，影响最大**）：仿真把过期指令**排队重放**

`board_link.py` 把板子发来的 `@MOVE` 行放进 FIFO，每渲染帧只取一行。板子 ~17 行/秒、
仿真渲染帧率受负载影响，两边稍有差池队列就积压 —— **仿真启动那 10 秒里板子就已经
发了上百行**，之后仿真逐行"重放"这些几秒前的指令。实测标定窗口里：

```
段号  指令   板子发出→仿真生效
  1   上      +1.55 s
  3   左      +1.46 s
 ...         逐步减小
 43   左上    −0.03 s   ← 队列清空后才正常
```

也就是说**闭环里板子的决策平均要晚 1~4 秒才作用到平台上**（启动阶段更久）。
这不是视觉问题，但会被误读成"决策滞后/角色不听话"。

修法：队列最多留 **2** 条（超出丢最旧的，计数 `n_stale_dropped` 并显示在 HUD 上）；
`test_stdin_transport_maps_move_to_action` 要求"一次读到两行时顺序保持"，
上限取 2 正好两者都满足（41 个 `test_board_link` 用例全过）。

修完后真值侧实测：**指令→动作 0.015~0.070 s**（同一套 harness、同一条 ssh）。

### 13.4 真凶四（环境）：相机拍的是**物理屏幕**，窗口被盖住就全错

一次闭环跑里 `field_valid` 只有 59%、`ps_new` 只找到 6% 角色，看起来像"视觉退化"。
截屏（PowerShell 抓 Windows 桌面）一看：浏览器盖在仿真窗口上面，屏幕上根本没有场地。
新增 `tools/focus_sim.sh`（枚举窗口 → `SW_RESTORE` + `SetForegroundWindow`；**不能用
`SW_MAXIMIZE`**：全屏窗口再最大化会被改尺寸，场地四角被推出屏幕，实测只剩一个标记），
并接到 `boot_cal.sh` / `criterion_collision.sh` 里。

### 13.5 重算后的真实精度（闭环跑 `/tmp/crit4`，1605 帧）

| 指标 | 之前（第 12 节） | 现在（按单调钟/轨迹对齐） |
|---|---|---|
| 角色绝对误差（时间对齐） | 中位 52 | 中位 45、p90 194 ← 仍含**时间抖动** |
| **角色离真值轨迹距离** | — | **中位 5.8、p90 15.0、91% ≤20 单位** |
| 角色静止帧误差 | — | 中位 16.0（平台不动时的纯几何） |
| 缺口中心 x | 中位 11、71% ≤20 | 中位 **5.4**、p90 18.2、**78% ≤20** |
| 墙 y | "偏置 −33、中位 52" | 中位 **8.8**、p90 75.8（墙自己的移动也含在里面） |
| 几何有效帧 | 98% | 89.3% |
| 最长观测空档 | — | 3057 ms（**不达标**，目标 ≤300 ms） |

**结论：视觉几何本身已经够准（离轨迹 91% ≤20 单位），误差的大头是"时间"** ——
端到端延迟 ~0.25 s（相机 60 ms + PL 24 ms + 处理 65 ms + 传输 + 仿真 0.75×），
在 200 单位/秒下就是 50 单位的"看起来偏"。

### 13.6 仍然存在的缺陷（下一步，有证据）

1. **空场地上"墙"是假的**：标定窗口里真值 `obstacles=[]`（2989 行全空），
   板子却 100% 的帧都报 `walls=2`。原因：`find_walls` 只用**亮度**判据，
   深色场地上的**网格线/外框**在自动阈值下也能凑出"整行亮"；而合同里的墙是
   **橙色**（实测相机里 `r−b` 60~118），网格/标记/角色都是**中性**（`r−b` ≈ 0~15）。
   → 下一步给 `find_walls` 加**颜色门**（`r−b` 与蓝分量双条件），亮度只做辅助；
   这同时能解决"墙 y 偏置"（现在抓的可能是墙的光晕而不是墙本体）。
2. **角色被误认成左上角标记**：空场地里 PS 检测器 63.8% 的帧给出的"角色"像素
   集中在 **(0..31, 0..31)** —— 就是左上标记；`player_field` 因此跑到 x=186..551 的
   乱值，标定窗口的"初始位置"直接失效（这也是 `boot_cal` 视觉侧数字崩掉的原因）。
   现有标记排除半径是 `2 × 标记宽`，实测不够。
   → 下一步：排除半径改由**合同**算（标记 48 场地单位 → 像素），并把
   "墙角/边框"也纳入排除。
3. **仿真周期性卡 2.9 s**（~35 s 一次）：`rtf` 从 0.82 掉到 0.48。它会让
   "指令→动作"在那一瞬间变成几秒。下一步查 pygame 全屏 + 120 Hz 物理的 pacing。
4. **虚拟真值**：现在有了可信的标定（速度 = 200 单位/仿真秒 × rtf ÷ 板子速率；
   延迟 0.015~0.07 s），可以按"板秒"积分了。注意 rtf 本身会变（0.75~0.83），
   所以积分只能用**平均值**，每帧仍要靠视觉校正（α=0.25~0.3）。

### 13.8 标定跑出来的数（`boot_cal.sh`，45 s 无墙窗口，752 帧）

| 量 | 值 | 怎么来的 |
|---|---|---|
| 初始位置 | **(330.1, 93.3)**，σ = (1.3, 0.6) | 头 1 s 停住，MAD 剔离群后取均值（真值 (320,105.6) → 偏置 (+10,−12)） |
| 平台速度 | **156.6 单位/板秒 = 143.7 单位/真实秒** | 把指令方向积分成 `S(t)`，网格搜延迟 + 最小二乘解 `p = p0 + v·S(t−lag)` |
| 分轴一致性 | vx 160.2 / vy 153.0 | 同一拟合的两个分量（差 4.5%，说明各向同性没坏） |
| 拟合残差 | 中位 **20.1** 单位 | 残差里含"视觉噪声 + 延迟抖动" |
| 端到端延迟 | **0.56 板秒**（≈0.51 真实秒） | 同一个拟合的 `lag`：板子发指令 → 相机看到它动 |
| 平台自身延迟 | **0.127 s**（真值侧，板秒 0.138） | 真值 `applied` 第一次变成该方向 |
| 契约对照 | 200 单位/**仿真秒** × rtf 0.75 = **150 真实单位/秒** | 与视觉的 143.7 差 4%，两条独立路径互相印证 |

**口径**（写死在 `calib.json` 里，别再混）：
`speed_units_per_board_s` 给**板子上积分**用；`speed_units_real_s` 只用来和真值对照；
`cmd_delay_board_s` 是"平台多快开始动"；`vision_latency_board_s` 是"你看到的画面
落后多少"—— 决策/预测要用后者，两者差 4 倍，混用就会预测过头。

标定窗口本身也验证了 `--obstacle-delay`：真值 3010 行 `obstacles` **全空**。

### 13.9 修完这些之后的闭环（110 s，同一套 harness）

```
视觉：1976 帧 / 118.4s = 16.7 fps；field_valid 99%；ps_new 角色 77%；非 stay 动作 1732
仿真：11452 步 = 95.4s；碰撞事件 24；最小间隙 -13.9，中位 59.4
```

对比修复前那一轮（窗口被浏览器盖住，**无效跑**：field_valid 59%、ps_new 6%）：
覆盖率回来了（99% / 77%），但**碰撞 24 次仍不达标**（判据④要求 0）。

现在可以确定碰撞不是"看不清"造成的了：几何误差中位 5.8 单位、缺口 5.4 单位，
而**端到端延迟 0.51 s 在 200 单位/秒下等于 100 单位**、墙自己还在以 ~128 单位/秒
向下压。决策层在**真值**上是 298/298 正确的，所以剩下的问题一定是"**用的世界状态
已经过期**" —— 这正是下一步要用标定后的模型做**预测**（虚拟真值）的地方：
按 `speed_units_per_board_s` 积分自己的位置、按墙的已知速度外推墙的 y，
再决策；视觉只做校正。

## 14. 虚拟真值服务的分工（2026-10-18 定案）：视觉只负责"初始化 + 发现新墙"

### 14.1 判据（为什么现在这么分工）

* 环上**角色是确定性的**：平台速度契约 200 单位/仿真秒，方向就是 8 个离散码 ——
  板子知道"我发了什么"，就应当知道"它现在在哪"。把视觉一直塞进决策，等于用一条
  0.5 s 延迟、抖动 ~20 单位的观测去覆盖一个本来可以精确积分出来的量。
* 环上**墙一开始是准的**：刚出现的几秒，墙的 y 和缺口 x 的视觉误差中位 5~9 单位；
  之后它只是沿 y 匀速下压（实测 128 单位/秒）。所以"新墙出现时量一次、之后积分"
  比"每帧重新量"更准，也省掉了每帧对旧墙的重复识别。
* 因此视觉的**全部职责只剩两件**：
  1. **角色初始位置**（头几十帧、平台静止时取稳健均值）；
  2. **发现新墙并量它的初值**（y / 缺口 x / 逼近速度）。
  其余交给积分，视觉**不再覆盖**已经在虚拟真值里的量。

### 14.2 设计

**角色（`VirtPlayer`）**

```
初始化：前 N≈30 帧（或前 1.0 s）内 player_field_valid 的样本
        → MAD 剔离群 → 均值 = p0（实测 σ=(1.3,0.6)，偏置 (+10,−12) 需再校）
积分：  每个动作码变化沿用时，p += u(code) × v_board × dt
        v_board = boot_cal 实测 156.6 单位/板秒（**板秒**，因为板子的时间基快 9%）
不再使用：player_field / ps_new / ps_pred / rtl 一律**不进决策**
重锚（唯一的例外）：连续 M=5 帧 |vision − virt| > R=60 单位 → 判定"积分坏了"，
        用视觉重新初始化一次（并记录事件）。正常跑不应触发。
```

**墙（`VirtWall`）**

```
发现：  视觉报出一道 y 与所有已有 track 相距 > 40 单位的墙 → 新建 track
初始化：取前 3~5 帧（该墙可见）的 y、gap_x、v_y 中位数 → 固定
积分：  y -= v_y × dt（v_y 实测 ~128 单位/仿真秒，按板秒换算）
冻结：  一旦 track 建立 ≥ 3 帧且初始化完成，**视觉不再更新它的 y / gap_x**
视觉继续负责：发现**新**墙（新出现的那一道）、以及"墙已经离场"的判定
选墙/瞄准：完全在虚拟真值上进行（已有 `select_threat_wall` + `gap_avoid`）
```

### 14.3 为什么这能解决当前的碰撞（有数据支撑）

| 现状问题 | 虚拟真值做法 |
|---|---|
| 端到端 0.56 板秒 → 位置误差 ~78 单位 | 积分的角色位置**零延迟**（只受标定误差 4% 影响） |
| 墙 y 每帧重测，光晕/行带让 p90 到 76 | 新墙量一次（中位 8.8）+ 匀速积分 |
| 旧墙仍在每帧被重新检测（占满 6 道墙的算力） | 旧墙冻结，算力集中到新墙 |
| 24 次擦边碰撞 | 目标：≤5（后续再压到 0） |

### 14.4 落地顺序（每步都可独立验收）

1. **离线验证漂移**：用已有 diag 日志，离线跑"只在初始化用视觉、其余积分"，
   量 45 s 后角色误差（目标 ≤20 单位）与墙 y 误差（目标 ≤8 单位）。
   工具：`boot_cal.py --path-fit` 已经给了积分模型；先把 `virt_truth.py`
   加 `--player-mode integrate --wall-mode freeze`，在旧日志上做 A/B。
2. **板子上接 `VirtPlayer`**：`main.cpp` 里角色字段改由积分给出，视觉只喂初始化；
   诊断日志加 `virt_player`、`player_init_age`、`reinit_count`。
3. **板子上接 `VirtWall`**：`wall_gap::find_walls` 的输出只用于"新墙/离场"，
   已冻结的 track 直接生成 `gap_avoid` 的矩形；日志加 `wall_age`、`wall_frozen`。
4. **验收**：`criterion_collision.sh` 碰撞数（目标 ≤5 再冲 0）、
   `vision_accuracy.py` 的 `field_valid`/空档（视觉负载下降应当让空档变小）、
   以及 `boot_cal.sh` 复跑确认标定值稳定。

### 14.5 已知前提（不满足就得回头改）

* 板子必须**听得懂自己的指令**（`@MOVE n` 的 8 方向 + 死区量化），且知道
  **自己实际发出的**是哪一码 —— 否则积分和现实会分叉（`st.last_cmd` 已具备）。
* 标定速度必须以**板秒**为单位（156.6），换成真实秒会差 9%。
* 墙的逼近速度要按**板秒**换算；它可以从"新墙初始化时的几帧"直接量出来，
  不必依赖仿真真值。
