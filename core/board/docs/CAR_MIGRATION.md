# 从"仿真平台"迁移到"真实二维小车"

> 结论先说：**只换前端**。把"图像 → 场地坐标几何"这一段换掉（斜视、地面投影、
> 自己当角色、只看见一两个标记），**下游一律不动**：`motion`（推速度）、
> `gap_avoid`（决策）、`action_codec`（动作号）、线协议、安全校验，全部按
> **场地坐标里的 `WorldView{player, rects}`** 工作 —— 这个接口就是迁移的接缝。
>
> 反过来说：任何"为了让小车能跑"而改**场地/墙色/角色大小/阈值**的做法都是错的，
> 那是在迁就相机，不是在迁移系统。

---

## 1. 差异清单（仿真屏幕 → 真实小车）

| 维度 | 仿真（现在跑的） | 真实小车 | 影响哪一段 |
|---|---|---|---|
| 视角 | 固定相机正对**屏幕**，接近正交 | 相机装在小车上，**俯视地面**、斜视、还会动 | 前端（图像→场地坐标） |
| 墙的形态 | 屏幕上的**水平长条**（图像空间就是矩形） | 地面上**投影/实体**，图像里是**四边形**，有透视消失点 | 前端 + 几何提取 |
| 角色 | 屏幕上的**白圆**（视觉找亮块） | **小车自己** | 前端（player 来源） |
| 参考物 | 四角 ArUco **全可见** | 最多看见**前方 1~2 个** | 标定（单应怎么解） |
| 尺度 | 全画面同一尺度 | 近处大、远处小（分辨率随距离衰减） | 前端（阈值/分辨率） |
| 盲区 | 无 | 车身挡住**最近的一小块地面** | 决策（近处不可见怎么办） |
| 运动 | 相机/墙都是屏幕里的像素运动 | 相机自己动 → 运动模糊 + 自身运动混进墙的速度 | 跟踪器（`motion`）+ 曝光 |
| 延迟 | 21.7 帧/秒链路（46 ms） | 同一套链路，但车在动 → 延迟变成位移 | 决策（预测）+ 安装 |

## 2. 迁移原则：接缝在"场地坐标几何"

```
[前端：图像 → 场地坐标]                       [下游：全部复用]
  斜视图像 ──单应/反投影──▶ 墙段(rect) ─┐
                                       ├─▶ motion(α-β) ─▶ gap_avoid ─▶ action_codec ─▶ 电机/键盘桥
  小车自身位姿 ──里程计/自定位──▶ player ┘
```

* 前端输出必须**只有**："几段墙（矩形，场地单位）+ 缺口 + 小车自己的位姿"；
* 前端**不许**输出"图像像素"给下游 —— 一旦下游看到像素，阈值、尺度、透视就会
  漏进决策，仿真里调好的东西在车上全部失效；
* 验收口径不变：**同一批几何（场地坐标）喂给 `gap_avoid`，C++ 与 Python 给出的
  `tier`/指令必须逐位一致**（`core/cpu/tests/test_cpp_gap_avoid.py`）。

## 3. 逐项怎么解

### 3.1 斜视 + 地面投影 → 先整流，再沿用现成的 2D 逻辑

* 现成的东西已经在仓库里：
  * `core/vision/calibration.py`：**参考物 → 单应 H → 场地坐标 + 尺度**（明确写了
    "画面的像素是斜视的"，必须换成世界长度才能判"缺口够不够宽"）；
  * `core/vision/localize.py`：**A. 单应映射（首选）**、**B. 地面反投影**（单相机 +
    已知安装高度 `h` + `pitch`，逐点 3 乘加 1 除，pitch 固定时三角函数可预算），
    还有"已知尺寸测距 `Z = f·W / w_px`"。
* 迁移动作：在**前端**加一步"整流"（`warpPerspective`，单应来自 3.1 的标定），把
  斜视画面变成**俯视场地图**；后面所有"找墙段 / 找缺口 / 量宽度"的逻辑**一行都不用改**
  —— 因为它们在场地坐标里本来就成立。
* 分辨率随距离衰减：整流后按**场地单位**给阈值（面积、宽度），不要按像素给；
  远处像素不够就限定"决策只看前方 N 米"（`gap_avoid` 的 horizon 本来就是这个意思）。

### 3.2 角色 = 小车自己 → player 的来源要可换

* 现在 `main.cpp` 的 player 来自**视觉亮块**（`f.player`）。车上是**自己**，没有"找
  自己"这回事：应该来自**里程计 / 自定位**（轮速 + IMU，用可见标记的单应把漂移拉回来）。
* 迁移动作：板子加一个 `--player-source vision|odometry|fixed`，把
  `WorldView.player` 的来源变成可配置；`gap_avoid` 完全不感知。
* 好处：车的速度估计比"从画面推"准得多（`motion` 的 α-β 在车上是给**墙**用的），
  `t_arr` 直接受益。
* 注意：`player.radius` 要换成**车的物理半径**（`core/standard/player` 那套契约），
  因为"缺口 ≥ 车直径"是平台硬约束。

### 3.3 只看见前方一两个标记 → 一个标记就够

* 单应 8 个自由度、每组点给 2 个方程 → **一个 ArUco 的 4 个角就解得出**（不需要四个
  标记全见）。`calibration.py` 里"4 组点就能解"说的就是这件事。
* 二义性与尺度：单标记位姿有 2 解 + 尺度不可辨，用**已知安装高度/俯仰**（`localize.py`
  的 B）和"车一定在地面上"这条约束定下来。
* 场地建议（要给主办方/自己搭场地时提）：标记**画大一点、多贴几个**（沿边贴一排，或
  地面贴网格），保证**任何时刻至少一个完整可见**；标记方向不要全同（同一方向的两个
  标记在斜视下容易混淆）。
* 前端要对"标记被墙挡住 / 只看到 3 个角"有明确降级：**这一帧不更新标定**（保持上一
  个 H，并打日志），绝不用半个标记硬解。

### 3.4 盲区 / 曝光 / 延迟

* **盲区**：车身挡住最近的一小块地面 —— "最近的墙"可能看不见。对策（按优先级）：
  1) 相机往前/往上装，盲区压到小于一个车长；2) 决策里对"盲区"加一个保守假设
     （把车前方 δ 距离内当成障碍，或按上一帧的墙速外推）；3) 物理保险杠兜底。
* **曝光**：车在动 → 必须短曝光（运动模糊会把墙段糊成一片）。这条在仿真里**测不出来**，
  必须在车上量（对着地面、以最大车速跑，看墙段宽度是否还稳定）。
* **延迟**：链路 46 ms（21.7 帧/秒，见 `core/board/README.md` §6.2 的实测表）。车在动时
  延迟 = 位移，`t_arr` 与 `gap_avoid` 的预测必须吃上真实速度（3.2 的里程计）。

### 3.5 墙在动（投影的变化）

* 仿真里的墙速度由 PS 从相邻帧推（`core/cpu/cpp/motion.hpp` 的 α-β）。车上同理，
  但要把**自身运动**先减掉（`physics/relative.py` 的 `to_player_frame` 就是这件事的
  仿真版）：否则"车往前走"会被推成"墙在靠近"。
* 如果投影节奏是**已知的**（主办方按固定速率投），把已知运动当先验喂进去，比纯估计稳。

## 4. 先在仿真里把"斜视路面相机"造出来当试验台（建议的第一步）

不要直接上车调。先在现有仿真里造一个**虚拟小车相机**：

1. 取俯视场地图（仿真现在渲染的就是俯视几何）；
2. 按"相机高度 `h` + 俯仰 `pitch` + 内参 `fx,fy,cx,cy`"算一个单应 `H`，
   用 `cv2.warpPerspective` 把它变成**斜视、地面投影**的样子（墙变成四边形、
   四角标记只有前方可见）；
3. 把这张图喂给**同一条视觉链**，前端先做整流，再看：
   * 整流后的墙段/缺口/角色位置，和**俯视真值**逐字段对账（仿真知道真值）；
   * 扫一遍 `h`/`pitch`/墙的位置，给出"哪些姿态下几何还能稳定恢复"的**可测区间**；
4. 这一步跑通再上车：车上唯一的未知量只剩"标定准不准"和"曝光/模糊"。

这条路径和项目已有的做法一致（**先仿真、再板子、再真机**，每一步都有离线判据），
而且它把"小车视觉"变成一个可以在 PC 上反复跑的回归测试。

## 5. 分阶段（每阶段都有可验收的判据）

| 阶段 | 做什么 | 判据 |
|---|---|---|
| C0 | 虚拟斜视相机 + 整流（纯离线，PC） | 整流后的墙段/缺口与俯视真值的误差 < 1 个场地单位 |
| C1 | 单标记单应 + 安装高度消二义（离线） | 只给前方 1 个标记时，恢复的场地坐标误差 < 2%；标记被挡住时明确降级 |
| C2 | player 来源换成里程计（板子上，仿真平台仍可用） | `--player-source odometry` 下，仿真里用"假里程计"喂位姿，决策与视觉版逐帧一致 |
| C3 | 盲区/延迟模型 | 故意遮住车前方 1 个车长的场地：决策不发"看不出来"的指令（保守/停） |
| C4 | 车上实测 | 真车以最大速度跑：墙段宽度稳定、`t_arr` 与实测到达时间差 < X% |

## 6. 明确**不**做的事

* 不为迁就相机改**墙色 / 角色大小 / 场地尺寸 / 难度阈值** —— 那些是平台契约
  （`core/standard/`），改了等于把"仿真里调好的"换成"这台相机刚好能看见的"；
* 不在板子上加"仿真专用"的分支（例如"因为屏幕是 4:3 所以 y 乘 0.75"）——
  这种特例在车上一律是错的；
* 不追求"四个标记全可见"才工作：明确支持**单标记**，并把它做成有日志的降级路径。

## 附：真机位实测（2026-10-17）——为什么必须先几何矫正

机位：UVC 相机固定对着 **1920x1080 全屏平台**，UVC 出 MJPG 640x480，
流水线裁成 640x360（`crop=640:360:0:60`）。四挡相机亮度各取一帧（板子上
`v4l2-ctl -c brightness=B` + `ffmpeg -frames:v 12`，丢热身帧）。

### 1. 在**正视图**（屏幕录制帧）上，缺口判据已经稳了

`core/vision/tools/gap_stability.py`（真场地帧 3 帧 × 9 组相机退化）：

| 退化 | 缺口中心 | 宽度 | 缺口 SNR |
|---|---|---|---|
| 干净 | 224 | 45 | 629 |
| 曝光 ×0.55 | 224 | 45 | 346 |
| 曝光 ×1.6 | 224 | 44 | 545 |
| 白平衡偏暖 | 224 | 44 | 671 |
| 白平衡偏冷 | 224 | 45 | 512 |
| 失焦 blur=2 | 224 | 45 | 459 |
| 噪声 σ=5 | 224 | 45 | 36 |
| MJPG q=50 | 224 | 44 | 474 |
| 全叠加 | 224 | 44 | 134 |

真值 224 / 45；**27 次测下来中心误差 0 px、宽度 ±1 px**。

### 2. 在**斜视机位**上，先坏的不是缺口，是**选墙**

同一套代码在真机位四挡亮度下，`best_wall_band` 锁到的带完全不一样：

| 相机亮度 | 最显著带（行） | 报出的缺口 | 说明 |
|---|---|---|---|
| 40 | 58..84 | 608（宽 64） | 选到上面那条墙 |
| 70 | 300..324 | 118（宽 40） | 选到**橙色场地边框**（洞是角标） |
| 100 | 19..42 | 44（宽 26） | 又换了一条 |
| 130 | 253..287 | 132（宽 38） | 又换了一条 |

场景里是 **2 条障碍墙 + 一圈同色边框**，所以"最显著那条"必然随曝光跳。
处理办法（已实现）：`wall_bands()` 把所有带都拿出来，`best_door()` 用**无量纲支撑比**
`min(左墙长, 右墙长) / 缺口宽` 判门 —— 边框角标洞实测 2 : 394（0.05），真门洞远大于 1，
不需要知道边框在哪。

### 3. 结论：斜视下几何先验失效，必须走 C1（矫正）

* 透视把门洞横向压到 **17~47 px**，而墙带在斜视下反而更厚（25~41 行）——
  **"缺口 ≥ 墙厚"这个先验只在正视图成立**，不能当成跨机位的判据；
* 缺口的**像素宽度**必须用**同一帧里的角色直径**做尺子，而不是墙厚；
* 这两个问题在**矫正到场地坐标之后自然消失**（正视图上的表格就是证据）。

所以下一步是 C1：`vision/calibration.py` 的 4 角标 homography → 正视图，
然后缺口/墙厚/支撑比全部按**场地单位**算。**在那之前不要动平台的墙色/角色尺寸**。
